# Deployment Guide (Render.com)

This document explains how to deploy the **backend** to Render.com so the native Android app
(and the web app) can talk to a public HTTPS API.

## Status (important)

At the time of writing, `https://mindease-backend.onrender.com` was returning **HTTP 503**.
503 on Render usually means one of:

- The web service never completed a successful boot (dependency or startup error).
- The health check is failing and Render keeps restarting the service.
- The service is stopped/out of credits.
- Cold start is still in progress (free tier sleeps after 15 minutes of inactivity).

The mobile APKs were built pointing at this URL, so getting the backend to boot is the **only
remaining action** before the app is fully usable on mobile data/Wi-Fi.

## Backend deploy (Render)

A ready-to-use blueprint lives at the repo root: **`render.yaml`**. It provisions:

- `mindease-backend` — FastAPI web service (Python runtime)
- `mindease-db` — managed Postgres (free)

### Option 1 — Blueprint deploy (recommended)

1. Push the repo (including `render.yaml`) to GitHub.
2. In the Render Dashboard: **New + → Blueprint** → select the repo.
3. Render creates the web service + Postgres automatically using the values in `render.yaml`.

Setup performed automatically:
- `DATABASE_URL` / `SYNC_DATABASE_URL` come from the managed Postgres.
  The app normalizes the `postgres://` scheme to the asyncpg driver automatically
  (see `backend/app/core/config.py`).
- `JWT_SECRET` / `ENCRYPTION_KEY` are auto-generated by Render (`generateValue`).
- `CREATE_TABLES_ON_STARTUP=true` → tables are created on boot.
- The start command runs `python -m seed_data` first, so demo accounts exist:
  - `demo@mindease.ai` / `demo123`
  - `counselor@mindease.ai` / `counselor123`
  - `admin@mindease.ai` / `admin123`

### Option 2 — Manual web service

1. Create a **Web Service** from the repo.
   - Root directory: `backend`
   - Environment: `Python`
   - Build command: `pip install -r requirements.txt`
   - Start command: `python -m seed_data && uvicorn app.main:app --host 0.0.0.0 --port $PORT`
   - Health check path: `/health`
2. Create a **PostgreSQL** database (free plan) and add `connectionString` to the web service
   as both `DATABASE_URL` and `SYNC_DATABASE_URL`.
3. Add other env vars (see `backend/.env.example`):
   - `JWT_SECRET`, `ENCRYPTION_KEY` (generate with `secrets.token_hex(32)`)
   - `AI_PROVIDER=mock` (demo works with no API key)
   - `CORS_ORIGINS=https://mindease-frontend.onrender.com,http://localhost:3000`
   - `CREATE_TABLES_ON_STARTUP=true`

### Verify

```
https://mindease-backend.onrender.com/health        -> {"status":"healthy"}
https://mindease-backend.onrender.com/docs          -> Swagger UI
```

And from the native app:
```
POST https://mindease-backend.onrender.com/api/auth/login
{"email":"demo@mindease.ai","password":"demo123"}   -> 200 + access_token
```

## Notes

- Free-tier Postgres: Render provides the URL with `DATABASE_URL` scheme; the backend
  normalizes it, so no manual scheme surgery is needed.
- Free web services sleep after inactivity; first request after a nap may take 30–90 s to boot.
- If you switch to a paid Postgres or a different region, update `render.yaml` accordingly.
- The **frontend** continues to deploy separately as `mindease-frontend.onrender.com`.
- The **dev APK** (`mindease-ai-dev-LAN.apk`) targets `http://10.114.11.118:8000` and only works
  while the backend runs locally on the laptop and the phone is on the same Wi-Fi. It is for
  development only — never ship it to users.
